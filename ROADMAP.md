## Shipped

- **Machine-readable state, cursor budget, statusline drift (v0.9.0).** Three changes so a `NOW.md` cursor stays lean and an external reader never has to parse its prose. (1) The `Stop` hook now writes `.now/state.json` next to the breadcrumb: a facts-only snapshot (schema v1) of the cursor (active thread and its line count, next action, queue and quick-fix counts), idea and shipped tallies with dates, the top roadmap intent, and git status (uncommitted, unpushed, last commit). Facts only, no thresholds, so consumers derive their own flags; missing source files become null sections; written atomically (temp file then rename) so a file watcher never catches a half-write. Hook rules held: silent, exit 0, opt-in marker gated, no-op outside a ClauDHD project. `git.uncommitted` excludes ClauDHD's own four root files (matching the brief's notion of drift), and `lastTouched` is the parsed date, not the freeform line. (2) `/claudhd:wrap` gained a cursor budget: [`budget.js`](plugins/claudhd/scripts/budget.js) measures the Active thread section against `ACTIVE_THREAD_LINE_BUDGET` (40, tunable in constants.js), and when it is over, wrap runs a migrate pass first (fully shipped bundles to SHIPPED.md, parked or future material to ROADMAP.md or IDEAS.md), leaving the thread with only its summary, live state, and next physical action. (3) [`statusline.js`](plugins/claudhd/scripts/statusline.js) reads state.json and shows one attention flag, worst first: `[over]` (past budget), `[drift]` (active but `Last touched` lagging by more than `CURSOR_DRIFT_DAYS`, default 3), or the existing mtime `[stale]`; pre-0.9 projects with no state.json still show `[stale]`. The active-thread line count is defined once in [`nowfile.js`](plugins/claudhd/scripts/nowfile.js), so the snapshot, the budget check, and the statusline flag all count the same way. Built to give a desktop dashboard (yardmaster) a clean parse contract, but nothing here depends on yardmaster existing; the plugin stays standalone. Adds `state.test.js` and `budget.test.js`, extends `checkpoint.test.js` and `statusline.test.js`; suite 72 -> 97.
- **Active-thread staleness flag (v0.8.0).** The only staleness guard keyed off the file's mtime / `Last touched:`, so a `NOW.md` kept fresh by an ever-growing header narrative hid an active-thread pointer that had gone stale underneath it (an 18-day-old thread in real use, never flagged). `brief.js` now tracks the active thread by its own identity (the first bold name in the section) and stamps first-seen in `.now/active-thread.json`; the clock resets when a different thread is promoted, and a thread that stays active past `ACTIVE_THREAD_STALE_DAYS` (default 14) raises a drift flag pointing at `/claudhd:wrap`. Independent of mtime, so a fresh-but-rotting cursor no longer hides it; a thread already stale when this ships starts its clock fresh. Adds `active-thread-staleness.test.js` (4 cases); suite 68 → 72.
- **Project roadmap (v0.7.0).** Reversed the "no project-level roadmap" non-goal, whose only justification was that the roadmap belonged to Cartographer and Compass. Both were sunset (cartobench killed the cartographer map premise, 0 doc reads in 48 runs; Compass was a connector over a missing leg), so the justification is void. Added a lightweight `ROADMAP.md` as the committed, ordered lane between IDEAS.md (someday) and the NOW cursor (one active thread): `## Now` / `## Next` / `## Later` / `## Shipped` / `## Non-goals`, plain ordered intents with no status schema (compass's `status`/`active_phase` tuples stayed dead). `/claudhd:roadmap` shows it or adds an intent, `/claudhd:init` scaffolds it, triage gained a route into it, and the SessionStart brief surfaces the top `## Next` line. The single-cursor rule holds: the roadmap orders many intents, NOW.md still points at one.
- **Quick-fixes hard limits (v0.6.1).** Tightened the lane so it can't become an avoidance backlog: cap lowered 5 → 3, and `/claudhd:quick` now states the hard limits explicitly — one file, one sitting, no schema/API/public-contract change, no broad refactor; a fix that fails its check is kicked back to `IDEAS.md` instead of sprawling. `quick.test.js` updated for the new cap (suite stays green).
- **Quick-fixes lane (v0.6.0).** Triage was binary: an idea either earned a spot in the single-focus Queue or stayed parked, which left small chores (a typo, a dead import, a rename) to either clog the cursor or get lost. Added a capped `## Quick fixes` batch to `NOW.md` plus `/claudhd:quick`: `/claudhd:quick <text>` appends a chore in one local, zero-token write (the [`idea.js`](plugins/claudhd/scripts/idea.js) pattern, lock and all); bare `/claudhd:quick` lists the batch so the command can clear it in one focused pass, kicking anything that turns out to need real thinking back to `IDEAS.md`. Triage gained a "ready but small" route into the batch, the `SessionStart` brief surfaces the waiting count and flags an over-cap batch as drift, and the lane self-heals into a `NOW.md` that predates it. The single-cursor rule holds — quick fixes are a batch, not a second active thread. Adds a 7-case `quick.test.js`.
- **Near-term hardening: drift filter, visit anchor, provider-neutral root, harvest tests (v0.5.2).** Four small correctness fixes. (1) The drift check filtered ClauDHD's own files by *basename*, so a real `docs/NOW.md` or `notes/IDEAS.md` was silently waved through as bookkeeping; now it matches the exact root-relative path git reports (`brief.js`, `init.js`). (2) The "shipped since you were last here" anchor was advanced on *every* `brief.js` run — including `/now`, `/regroup`, `/wrap` — so a mid-session `/now` swallowed the wins the next SessionStart should have shown. The anchor now moves only on an actual visit: the `SessionStart` hook passes `--record-visit`; the read-only commands don't. (3) All scripts now resolve the project root provider-neutrally: `CLAUDHD_PROJECT_DIR` → `CLAUDE_PROJECT_DIR` → cwd, so ClauDHD isn't hardwired to one host. (4) Added a test suite around `harvest.js` — the most Claude-specific, least-covered script — covering the `~/.claude/projects/<slug>` layout (redirected via `CLAUDE_CONFIG_DIR`), the incremental watermark, `--full`/`--dry-run`, the dedup-file listing, and the folder-name fallback. Suite grew 17 → 31 tests, green on Node 20/22/24 across Linux/macOS/Windows.
- **Capture-race fix + first test suite (v0.5.1).** `/claudhd:idea` did a read-modify-write on `IDEAS.md` with no mutual exclusion, so two captures racing (two open sessions) could clobber each other and silently drop a parked idea — the one failure a capture tool can't have. Fixed with a cross-process lock (atomic `mkdir`, stale-lock breaking) in [`lock.js`](plugins/claudhd/scripts/lock.js). Added a zero-dependency test suite under [`test/`](test/) using Node's built-in runner; the deterministic lock test proves two holders never overlap (and was verified to go red against a no-op lock). `harvest.js` was checked and does not write `IDEAS.md` itself — it emits guidance for the model, whose Edit fails loud rather than clobbering.
- **Branch-aware cursor (v0.5.0).** The committed `NOW.md` already rode the branch via git; the local `.now/` breadcrumbs were branch-blind. Now the `Stop` checkpoint also writes `.now/branches/<branch>.md` and the `SessionStart` brief reads the current branch's checkpoint and a per-branch "shipped since last visit" anchor (`.now/branches/<branch>.head`). The brief no longer flags ClauDHD's own live files (`NOW.md`, `IDEAS.md`, `SHIPPED.md`) as uncommitted drift. Serves the "I switch branches too often and lose my place" workflow with no new machinery — git swaps the cursor, ClauDHD swaps the breadcrumb.
- **Feature-scoped init doctrine.** `/claudhd:init` scopes the cursor to the *work*, not the repo. A feature spanning several repos gets one cursor per repo, each holding that repo's slice.

## Non-goals (decided, not "later" — see README)

- **No cross-repo / multi-repo "workspace" cursor.** A feature that spans repos gets one cursor per repo. A global workspace cursor would mean cross-repo state, a sync layer, and a global index — a second, heavier product. Killed deliberately to keep ClauDHD lightweight and zero-dependency. The per-repo, feature-scoped cursor already covers the common case (you only ever type in one repo at a time).
- **No multi-agent orchestration.** ClauDHD is a continuity / anti-drift tool, not a task runner or workflow harness.
- **One active thread per repo (or per branch).** The single-cursor constraint is the point, not a limitation to engineer around.

## Why this file exists

Eating our own dog food: the design conversation that produced v0.5.0 generated a pile of ideas, and a tool about resisting scope-drift has no business letting its *own* good ideas evaporate or quietly become scope creep. Capture, then triage: build the smallest real thing, write down what you killed and why.
